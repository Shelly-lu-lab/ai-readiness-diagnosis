# 正式报告模板契约 v0.8

最后更新：2026-08-17

本文档继承 [v0.7 报告模板契约](./report-template-contract-v0.7.md) 的结构化总体画像、证据边界和历史兼容规则。v0.8 只升级新生成报告的行动选择、行动卡和完整发展地图，不修改42道题、v1.1计分、45／55／70阈值、五类定位、既有诊断 ID 或既有报告快照。

## 1. 报告章节

报告只保留一个“下一步行动计划”章节，固定按以下顺序展示：

1. 优先判断摘要：说明本次从完整发展地图中筛选出多少项当前优先行动。
2. 当前优先行动：展示3—5张精炼行动卡。
3. 后续完整发展地图：保留本报告适用的全部维度，网页默认折叠，打印和 PDF 自动展开。

行动卡必须展示优先级、个人／组织属性、维度与分数、行动模式、为什么现在做、具体动作、完成标准和建议周期。用户正文不得展示题号、规则 ID、片段 ID 或行动族 ID。

## 2. 数量与分组

- 个人26题报告：3—5条个人优先行动。
- 个人42题观察报告：2—3条个人行动和1—2条需团队核实的组织建议，总计3—5条。
- 正式组织报告：3—5条组织行动。
- 同一行动族只保留一条；同一维度最多两条；相同输入和版本的数量、顺序与正文完全一致。
- 个人观察中的组织建议必须写明“来自个人观察、需要团队共同核实”，由有权限的经理或相关团队决定和推进，不把改变组织机制的责任交给员工个人。

## 3. 选择与行动模式

`RecommendationSnapshot` 新增可选字段：

- `actionMode`: `improve | stabilize | validate | scale`
- `selectionReason`: 面向报告读者的固定中文入选理由

新 v0.8 快照必须写入两个字段并纳入规范化内容哈希；旧快照没有字段时仍按原字节和原制品验证。

| 维度分 | 可进入优先池的方式 | 行动模式 |
|---|---|---|
| `<45` | 低分维度或具体题项发展信号 | `improve` |
| `45—54.9` | 已有尝试但尚不稳定 | `stabilize` |
| `55—69.9` | 仅限具体题项发展信号、影响差距、安全前置或必要验证 | `validate` |
| `>=70` | 只能验证效果或在边界内扩展，不得补短板 | `validate` / `scale` |

100分维度不得出现“优先改善”“尚未形成”“补短板”。全满分报告仍输出3—5条行动，但只能验证成熟做法或有边界扩展。

排序固定为：安全／核查／治理前置动作 → 具体低分题项信号 → 低分维度 → 已实现AI影响差距 → 已提供的背景障碍 → 完整发展地图回退。同层按维度得分升序，再按稳定行动 ID 排序。

## 4. 完整发展地图

完整发展地图不参与“当前优先行动”的数量限制，始终保留适用维度：个人专项4维、组织专项4维、组合报告8维。每个维度按既有45／55／70边界进入 `improve`、`stabilize`、`validate` 或 `scale`，用于说明后续阶段，不把所有维度伪装成当期优先事项。

## 5. 版本与历史

新报告使用：

- `expression_version=fixed_v0.8`
- `profile_narrative_version=profile_narrative_v0.1`
- `diagnosis_action_library_version=v0.2`
- `action_selection_version=action_selection_v0.2`
- `development_pathway_version=development_pathway_v0.3`
- `report_template_version=v0.8`
- 签名制品 `rule-artifact-v0.8`

v0.7 原制品、内容哈希、公钥和签名以 retained 历史制品注册；v0.2—v0.6 继续保留。历史报告按其冻结 manifest、制品和内容哈希验证，不用 v0.8 重算或改写。

## 6. Web/PDF 同源

网页和 PDF 读取同一 `report_snapshot.recommendations` 与 `developmentPathway`。网页发展地图默认折叠且可通过键盘操作；打印和 PDF 自动展开。行动模式和入选理由属于快照正文，任何渠道不得重新排序、重新选择或临时改写。
