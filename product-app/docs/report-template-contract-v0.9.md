# 正式报告模板契约 v0.9.3

最后更新：2026-08-18

v0.9.3 继承 v0.9.2 的确定性统一证据与故事线，将员工群体、部门和组织题项配对结果的最低样本门槛从7份调整为2份。2—29份一律标记为方向性结果，并固定展示“样本量较小、不得用于个人识别、排名或人员评价”的边界。v0.9.2及更早快照继续按 retained 制品验证和重放。

它不修改42题、26题配置、BG题、v1.1计分、45／55／70阈值或五区分类。

## 1. 冻结链路

新报告固定按以下顺序生成：

`score snapshot → behavior evidence → report storyline → integrated profile/action snapshots → report snapshot → Web/PDF`

相同输入与版本必须产生完全相同的结构化字段、中文正文、顺序和内容哈希。不得使用生成式 AI 临时润色。

## 2. 行为证据

每个维度保存 `BehaviorEvidenceSnapshot`：维度分、题项分布类型、分布统计、已形成行为、发展行为、整体含义、具体行为、实际影响或风险、解释边界、来源片段 ID 和证据 ID。

题项分布互斥分类为：

- `uniform_high`
- `uniform_mid_high`
- `uniform_mid_low`
- `uniform_low`
- `mixed_polarized`
- `insufficient`（有效数据不足，不属于五类有效分布）

全高必须展开该维度完整行为组合；全低只归纳2—3项关键行为；混合同时说明已形成部分和主要断点。组织群体分布使用达到样本门槛的共同有效样本解释。

## 3. 统一故事线

`ReportStoryline` 分别保存个人AI实践能力、组织准备度／个人组织观察和已实现AI影响的阶段，不得把八维或三项结果平均成单一整体阶段。`ProfileNarrative` 基于同一故事线固定生成四个正文角色：

1. 整合状态：这个人或组织目前整体是什么状态；
2. 工作链：哪些具体行为已经从任务说明连接到使用、检查和复盘；
3. 断点与影响：链路在哪里中断，以及可能带来的返工、质量、风险或价值限制；
4. 下一步优先：为什么先做当前行动，满足什么依赖后再扩展。

解释边界使用独立 `boundaryNotice`，不占用主体段落。每个正文块必须带维度、诊断、题项片段和证据引用；正文总长度不得过短，也不得用维度名单或轴分差代替画像。

优势、发展、总体画像、双轴定位和行动计划都从同一故事线取顺序和关系。同分不得按维度 ID 制造相对优势；全部A维100时四维全部列为并列成熟。

## 4. 逐维叙事

每个维度必须回答：整体含义、具体行为、实际影响或风险、解释边界。A维使用个人行为语言；个人42题的B维只描述“你观察到／较少观察到”，并明确需要团队核实；正式组织使用员工群体证据；管理者报告明确单人观察边界。

## 5. 行动与依赖

行动保持3—5条总量。治理、人工复核或异常入口低于45时，治理核实排在第一，所有高分个人路径降为 `validate`，不得出现 `scale`。个人观察中的组织行动先核实，再由授权角色推进。组织行动为0时不得隐藏组织区，必须写入 `observerOrganizationNoActionReason`，说明是高支持无具体断点、证据不足、组织数据不足，还是因优先级／责任边界未进入当前行动，并说明继续观察什么。

A3个人行动使用“拿一份真实AI结果做四步检查”：核对关键说法的原始出处、重算数字、查找遗漏或矛盾、检查敏感信息与人工批准要求；连续三份结果都留下发现、修改和最终采用或停用决定，才算完成。

Web 按个人组 `P1…`、组织组 `O1…` 独立连续编号。行动周期分近期启动（1—2周）、稳定方法（2—6周）和系统建设／扩展（6—12周），完成标准必须能在建议周期内实现。

## 6. 内容质量门

新报告生成时执行：矛盾检查、并列检查、视角检查、重复句检查、行动责任／周期检查、四段整合画像结构与长度、具体行为证据覆盖、A3可执行性，以及组织0项原因完整性。命中阻断问题时不得发布快照。

禁止用户正文出现“更值得先处理”“更值得先核对”“较少报告”“群体较普遍报告”“工作重构条件来承接”，并限制连续重复“从你的观察看”。抽象判断后必须给出具体行为。

## 7. Web/PDF

Web 与 PDF 只读取同一冻结快照。PDF 渲染必须显式展开完整发展地图，等待字体加载，保护行动卡／维度卡不跨页，避免孤立标题，显示页码。公开个人报告水印为“仅供个人发展参考”；企业和内部报告保留“内部资料·仅限授权使用”。PDF 文档标题取报告标题。
