# AI 组织转型诊断正式产品

这是正式产品 V1 的独立全栈工程。`prototype-*` 和本地 Alpha 仅作为历史设计与验收样机，不再作为生产代码基础。

## 当前可运行闭环

- 首页明确分为“开始个人测评”和“企业使用”两条路径；平台总管理员使用独立的 `/platform/login` 入口。邮箱验证会保存登录意图，不再把企业管理员误导到“我的报告”。
- 同一邮箱可以同时拥有个人账户、一个或多个企业成员身份及平台角色。登录时按入口直达对应工作区；登录后可从账户菜单切换，不需要重复验证邮箱。企业所有者／HR默认进入活动首页，管理者默认进入报告中心，员工默认进入个人中心。
- 平台管理员从“企业客户”页直接创建和管理真实企业，创建者取得该企业的显式 `owner` 成员关系并可进入工作台；普通邮箱不能创建企业。只有账号确实属于多个企业时才显示“我的企业”列表，不再把工作区选择作为所有管理者的默认首页。首次发布活动前必须完成企业基本资料，企业研究授权为独立选项。
- “我的报告”按全局邮箱账户聚合公开个人测评和本人在各企业中有权查看的个人报告；详情与PDF仍逐份执行本人身份校验，不因工作区切换扩大权限。
- 公开个人入口在工作背景之后提供26题“只了解我自己”和42题“同时了解我和所在组织”两种范围；42题结果固定为个人观察视角，不生成团队报告或员工共识。
- HR 创建个人、组织或个人及组织活动，选择匿名/实名及组织测量方法。
- 草稿活动可在发布前完整编辑或永久删除；发布后配置冻结，只能按状态机取消、关闭和归档。
- 开始时间在未来的活动发布后进入“待开始”，可预先发放带开放时间的飞书卡片；Worker 到点自动转为“进行中”，HR 也可明确提前开始。
- 进行中的活动可延长截止时间；系统追加保存原时间、新时间、原因、操作者和序号，不允许缩短或覆盖历史，并在保存后直接进入带新截止时间的飞书提醒编辑。
- 活动状态转换使用数据库条件更新；HR与Worker同时开卷或关卷时只执行一次状态审计和报告生成，重复请求幂等返回当前状态。
- 发布后生成带签名和有效期的员工入口。入口凭证放在 URL Fragment 而非查询参数，进入页面后立即从地址栏清除；生产环境还会将凭证中的参与者与当前飞书身份及租户强绑定，转发给其他员工无法作答。
- 实名活动提交后可立即回写完成状态；匿名活动不同步回写邀请。系统只在身份邀请域生成不含答卷、请求或Trace标识的一次性回执，经15—45分钟随机延迟后由Worker按批次随机顺序回写“已完成”。
- 员工入口的签名有效期覆盖活动截止后的90天，避免较长活动或常规延期导致原飞书卡片在截止前失效；是否允许作答仍由服务端的活动状态、开始时间和最新截止时间决定。
- 员工在阅读并确认版本化隐私说明后完成 16/26/42 道正式题目；答案在浏览器和服务端进行版本化保存，选择后自动进入下一题。
- 员工提交前会看到最终确认，明确已完成题量及“提交后不可修改”；确认期间防止重复操作。若浏览器因网络原因重试或产生并发请求，服务端返回第一次已经冻结的同一答卷、分数和报告，并重新签发报告取回凭证，不生成第二份数据。
- HR 可逐题启用 BG01—BG03；背景答案独立保存，不进入42题计分。
- HR 可增加最多5道企业补充题：单选、多选及实名活动的选答简短文字题；最多2道选择题可设为必答。补充题随问卷发布快照冻结、支持断点续答，但不进入计分、诊断、常模或标准复测比较。匿名结果仅在活动关闭且`n>=5`时汇总展示；实名文字原文查看会显示风险提示并记录审计，且不进入报告或PDF。
- 提交时在服务端冻结答卷、分数与完整报告快照。
- 个人或组合活动即时生成完整个人报告；组织活动关闭后按样本规则生成组织报告。
- 管理者单人组织自评允许 `n=1`；员工群体组织报告当前门槛为 `n>=2`。`n=2—29` 统一标为方向性结果，并明确禁止个人识别、排名和人员评价。
- 报告生成、内容审核和对外发布是三个独立状态：个人报告由确定性规则自动以 `system` 审核并发布，组织报告必须由有权限的HR完成审核和发布。
- HR 可把已发布报告的固定建议转成真实行动计划；计划冻结来源报告、目标维度、证据与风险边界，并记录负责人、资源、日期、里程碑、成功指标和90天复测节点。
- 同一报告中的同一建议只能转换成一个行动项；重复或并发请求返回已经创建的行动，不会产生两份计划。
- 行动计划支持0—100%进展、里程碑状态、追加式复盘历史和完成锁定，不会用新说明覆盖旧记录。
- 个人报告支持按飞书身份跨设备找回；实名个人报告采用活动级独立授权，不与团队报告授权混用。组织报告支持带到期时间的查看/下载授权，HR可查看全部授权历史并立即撤销。
- 员工可对实名身份关联的全部测评数据，或持有有效报告凭证的单次匿名数据发起删除；请求按“已排队—处理中—已完成/失败”留存状态，答卷、分数、个人报告和PDF由Worker异步删除，并返回对象存储、业务数据库和依法保留审计三部分处理清单。
- 组合测评的组织报告发布后，系统生成二阶段个人报告；HR选择员工受众时，同时生成不含部门点位的员工组织摘要。
- 报告发布按“报告＋受众”幂等；每份发布记录保存 `reviewed → published`、审核/发布主体及时间，重复点击或网络重试不会重复生成二阶段个人报告、员工摘要或审计事件。
- 组织报告支持达到门槛的多部门双轴定位：`n<2`不展示、`2—29`标为方向性参考、`n>=30`标为标准展示。
- 管理者单人组织自评必须实名并锁定一名指定评估人；报告明确标记为单一视角，不生成员工共识、部门比较或员工组织摘要。
- 每个维度保存确定性诊断 ID、题项模式 ID、实际片段、题项统计和逐题抑制原因；个人内部差异与组织配对样本均由固定规则生成。
- 报告模板 v0.9.3 沿用总体评价的“整合状态、工作链条、断点影响、下一步重点”四个语义角色，并把员工群体最低样本调整为2人；2—29人的整体、部门和题项结果固定显示极小/小样本方向性警示。三条轴分别定级，八维卡片固定展示整体含义、具体行为和影响或风险。网页与PDF读取同一冻结快照，并通过语言重复、抽象措辞、证据覆盖和责任越界质量门。
- 行动引擎已编译个人32条、组织32条及6条背景情境建议；每条快照保存触发事实、所需题项片段、证据等级、行动族和入选／抑制审计原因。
- 建议库启动时会校验数量、ID唯一性、证据引用、链接与内容边界；自动化回归证明64条主建议都能由合法分数或题项模式触发。当前建议内容仍标记为内部试点稿，待业务与方法专家正式审核。
- 新活动可关联题目范围和测量方法一致的历史组织报告，生成三项结果与八维变化；变化仅作描述性比较，不解释为干预效果。
- 企业设置支持飞书通讯录、用户角色、企业研究档案和常模候选数据授权。
- 飞书发放弹窗直接读取已同步通讯录，支持按部门查看、全选或逐人勾选；活动发布时冻结全员目标总体并拦截范围外邀请。
- 活动发布时冻结抽样框、问卷版本、企业研究档案与常模资格快照。
- 网页和打印/PDF 共用同一个确定性报告快照；PDF每页标注“内部资料·仅限授权使用”及快照版本，每次成功或失败下载均记录访问通道、角色、报告类型和内容哈希审计。
- 报告快照只收录本报告实际使用的证据来源、链接、支持范围与使用边界，避免把机构权威误写成干预效果证明。
- 飞书通知失败会进入 Redis 指数退避重试，任务状态和每次尝试均可审计；已经发送的任务会幂等去重。Worker 同时负责待开始活动的自动开放和到期活动的自动关闭。
- 报告内容采用规范化 JSON 哈希，可抵抗 PostgreSQL JSONB 字段顺序变化并支持确定性历史重放。
- 活动发布时生成不可变 `questionnaire_release`，冻结题目、背景题、企业补充题、量表、版本和可执行规则哈希；旧活动与当前运行规则不匹配时阻断作答，不静默换题或重算。
- 规则发布、Ed25519签名规则制品、评估输入快照、计分运行、分数快照和报告快照使用数据库强外键串联。历史重放先验证规则制品哈希与数字签名，再验证冻结报告内容；不使用当前模板重新生成历史报告。这些完整性证据不代表问卷已完成心理测量验证。
- 数据库升级会先为旧分数和报告重建不可变来源链，再把规则与输入引用设为非空强约束。
- 飞书 OAuth `state` 同时绑定发起登录的浏览器、服务端一次性消费记录与10分钟有效期；生产 Session 使用 `__Host-` Cookie，所有 Cookie 认证的写接口校验 `Origin`，防止登录重放、Session 置换和跨站写请求。
- API 日志的请求 URL 只保留路径，不记录问卷邀请、报告取回或渲染凭证等查询参数；Cookie 和 Authorization 请求头显式脱敏。
- API 提供仅 Worker 内网凭证可访问的 Prometheus 文本指标，包含请求量、5xx、在途请求、耗时、运行时间和内存；未处理错误同时向前端返回与服务端日志一致的 `errorId`。
- `/ready` 按当前数据库版本的精确记录判断就绪，不再依赖多个历史版本的时间排序；当前结构版本为 `2026-08-25-v33`。新数据库同时保留v0.2—v0.9.2历史制品与当前v0.9.3签名规则制品，历史报告按原快照验证，不用新模板静默重写。

## 本地启动

要求 Node.js 22 或以上版本。

```bash
npm install
npm run dev
```

浏览器访问 [http://localhost:5173](http://localhost:5173)。本地默认使用 PGlite 数据库和邮箱验证码登录；数据保存在 `.data/`。自动化浏览器测试会显式切换到隔离的开发模拟身份。

本地未运行 Redis 时请保持 `REDIS_URL` 为空；评分和报告网页仍可同步生成，只跳过 PDF、通知重试等后台队列任务。生产环境必须配置可用的 Redis。

如需在本地完整验收邮箱验证码版本，先复制 `.env.example` 为 `.env`，将 `AUTH_MODE` 保持为 `email_otp`，把 `PLATFORM_ADMIN_EMAILS` 设置为平台运营邮箱。当前无自有域名的 MVP 默认使用专用 Gmail SMTP：配置 `EMAIL_PROVIDER=smtp`、`SMTP_USER`、Google 应用专用密码 `SMTP_PASS`，并让 `EMAIL_FROM` 使用同一 Gmail 地址；不得填写 Google 账户登录密码。项目仍保留 Brevo 与 Resend 适配器，待有可认证域名时可以切回交易邮件服务。开发启动会自动读取项目根目录 `.env`。只有显式使用 `EMAIL_PROVIDER=console` 时，验证码才会显示在登录页，邀请和报告邮件不会实际投递；生产环境会拒绝该模拟模式。公开个人入口为 `/personal`，企业入口为 `/enterprise`，平台运营入口为 `/platform/login`。企业邮箱发放同时支持 CSV 导入和手工输入并自动去重；个人报告生成及面向员工的团队结果发布会发送报告就绪邮件。

也可以在 macOS 双击 [`启动正式产品.command`](./启动正式产品.command)。

## 质量检查

```bash
npm run check
npm run test:e2e
npm run test:e2e:email
```

`check` 包含 TypeScript、规则与 API 测试、正式构建。`test:e2e` 使用工程内自包含的 Node/Playwright 启动 API 和网页，用浏览器走完公开首页、企业活动创建、发布、截止时间延期、42题、背景题及企业补充题作答、提交、完整报告、PDF、建议转行动、进展更新和复盘历史链路。`test:e2e:email` 在已启动的邮箱本地环境中验证公开首页、邮箱验证码、个人工作背景、独立研究授权、真实账户和手机布局。API测试另覆盖匿名隔离、匿名完成回执延迟批处理、跨租户访问、隐私同意、实名个人报告独立授权、服务端草稿、补充题隐私边界、截止时间追加记录、报告授权、未发布报告转行动阻断、行动状态机、通知重试、报告重放和研究快照。

在 PostgreSQL、Redis 和 S3 兼容对象存储已启动的环境中运行：

```bash
npm run test:dependencies
```

该命令会真实建表、入队并读取 BullMQ 任务、创建对象存储桶并完成写入／读取／删除。`.github/workflows/ci.yml` 已将生产依赖烟测、完整浏览器验收和 API／Worker／Web 三类镜像构建组合成持续集成流水线。

## 工程结构

- `apps/web`：HR 工作台、员工作答页和完整报告。
- `apps/api`：活动、邀请、答卷、报告发布和行动计划接口。
- `apps/worker`：PDF、通知、删除和历史重放的异步任务入口。
- `packages/domain`：42题、计分、维度、分型与样本规则。
- `packages/reporting`：固定诊断解释、建议与报告快照组装。
- `packages/database`：PostgreSQL/PGlite 模型和仓储。
- `packages/contracts`：跨模块不可变对象与接口类型。
- [`docs/production-environment-input-checklist.md`](./docs/production-environment-input-checklist.md)：公司需提供的云资源、飞书应用配置、密钥交付、自动验收和 F01—F10 真实联调清单。

## 生产边界

当前是“可运行的正式产品工程和内部技术试点版”，不是已经部署上线的生产服务。真实员工数据进入前仍需完成：

1. 配置正式 PostgreSQL、Redis、对象存储和 HTTPS；服务端 PDF 归档与下载已实现，但仍需在目标云环境验证真实对象存储读写。备份、恢复和监控见 [`docs/production-runbook.md`](./docs/production-runbook.md)。
2. 提供飞书企业自建应用的 App ID、App Secret、回调域名和所需权限，完成真实免登、递归通讯录同步、卡片发送、提醒与失败重试验收。
3. 配置生产域名后执行真实租户、角色、匿名隔离、报告下载和跨设备找回的安全验收。
4. 完成公司信息安全审批及10—20人实名技术试点、独立匿名测试后，才可导入真实员工数据。

## 生产启动与容器

- `npm run build` 后可直接执行 `NODE_ENV=production node apps/api/dist/server.js`；内部工作区包的生产导出固定指向已编译的 `dist`，不会在生产环境临时执行 TypeScript。
- 邮箱正式流程和生产启动都不会写入示例租户或演示管理员；`SESSION_SECRET`、`DATA_LINK_SECRET`、`INVITE_SECRET` 与 `INTERNAL_WORKER_SECRET` 必须分别配置且互不复用。答卷去重、报告找回和草稿关联使用独立的稳定数据关联密钥，日常轮换 Session 密钥不会改变历史结果。邮箱模式下仅 `PLATFORM_ADMIN_EMAILS` 中的平台管理员可创建企业；创建者获得显式企业所有者成员关系。飞书模式仍通过 `FEISHU_BOOTSTRAP_OWNER_OPEN_IDS` 预先授权初始所有者。
- `Dockerfile` 包含 `api`、`worker`、`web` 三个目标；Web 由 Nginx 承载并把 `/api`、`/public` 和 `/health` 反向代理到 API。
- `infra/docker-compose.production.yml` 只接收外部 PostgreSQL、Redis 和飞书凭证，不在正式编排中创建带默认密码的数据库。所需变量缺失时会直接拒绝启动。
- 当前开发机没有 Docker，因此本轮已验证原生生产启动和健康检查，容器镜像仍需在具备 Docker 的测试或 CI 环境完成真实构建验证。
- 产品工程已提供 `.github/workflows/ci.yml` 和 `npm run test:dependencies`；只有流水线实际绿灯后，才能把 PostgreSQL、Redis、MinIO 与镜像构建状态标记为已验证。

因此，目前可以直接用于本地合成数据和内部流程验收；在上述外部资源与审批完成前，不应宣称已生产上线，也不应导入真实员工数据。

工程实现不改变42道题、v1.1计分和“尚待正式心理测量验证”的科学边界。
